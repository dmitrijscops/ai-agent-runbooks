# IT Service Desk Insights Agent — Overview

## Scenario Overview

**Scenario Type**: IT Service Management (ITSM) / Employee Support
**Agent Type**: Read-only declarative agent in Microsoft 365 Copilot (Agent Builder)
**Primary Tools**: Microsoft 365 Copilot, Agent Builder, ServiceNow Knowledge + Catalog Copilot connectors
**Complexity**: Intermediate
**Status**: Implementation guide available; tenant configuration and validation required

This scenario covers knowledge article and service catalog answers inside Microsoft 365
Copilot. It uses the Copilot chat harness and does not configure live incident tools,
endpoint diagnostics, or record mutations.

For investigation and controlled actions, use the separate
[IT Service Desk Insights Agent (GHCP)](../IT-Service-Desk-Insights-Agent-ghcp/1.Overview.md)
scenario, hosted on the GitHub Copilot harness inside Copilot Studio. Neither scenario
requires deploying the other.

---

## Problem Statement

Service desk teams and employees need consistent answers from hundreds of knowledge
articles without searching every source separately:

- **Answers depend on who you ask.** The same question can succeed once and return
  "I couldn't find that" the next time.
- **Knowledge is siloed.** Employees search ServiceNow separately from SharePoint.
- **Language handling is inconsistent.** The answer should follow the user's language,
  even when the knowledge base is written in another language.
- **Access must follow source permissions.** Restricted runbooks and region- or HR-scoped
  articles must remain restricted in Copilot.

---

## Solution Summary

The agent is a **declarative agent in Microsoft 365 Copilot**, grounded on ServiceNow
content indexed into Microsoft Graph by the **ServiceNow Knowledge** and **ServiceNow
Catalog** Copilot connectors. Connector ACLs carry ServiceNow user criteria into the
index; retrieval is security-trimmed for the user.

**These connectors do not provide incident records or user feedback.** Ticket sentiment,
ticket themes, and feedback analysis require a separately authorized source. The baseline
must explain that limitation rather than infer those insights from knowledge articles.
The runbook retains conditional analysis instructions and negative tests for this boundary.

### Key Capabilities

| Capability | Description |
|---|---|
| Grounded knowledge lookup | Answers from knowledge articles and catalog items, with source citations |
| Knowledge themes | Groups retrieved article content with supporting references, not ticket-volume claims |
| Permission-trimmed retrieval | Users see only content their source permissions allow |
| Language mirroring | Answers in the question's language while preserving source references |
| Consistent evidence handling | Explains missing sources, thin evidence, and unsupported requests |

## Business Outcomes

| Outcome | Description |
|---|---|
| Deflect tier-1 questions | Employees self-serve knowledge and catalog answers |
| Reduce search effort | Bring approved ServiceNow and optional SharePoint guidance into one conversation |
| Keep knowledge honest | Use source evidence to identify stale or contradictory guidance |
| Preserve source access | Validate positive and negative permission outcomes before rollout |

## In Scope / Out of Scope

### In Scope

- ServiceNow Knowledge and Catalog connector deployment with user-criteria mapping
- Declarative-agent configuration in Agent Builder
- Source-grounded answers, citations, and knowledge-theme summaries
- Conditional analysis guidance that requires actual authorized ticket or feedback text
- Multilingual queries, explicit date ranges, and consistency testing
- Publishing and governance in Microsoft 365 Copilot

### Out of Scope

- Live incident status, ticket creation, updates, notes, attachments, or closure
- Nexthink device diagnostics or remediation and Dynamics case-management actions
- Ticket sentiment or feedback analysis without a separately connected, authorized source
- Numeric ticket analytics (counts, MTTR, SLA breach rates); use Power BI over the
  ServiceNow data warehouse rather than treating retrieved samples as the full population
- Catalog ordering or replacing the ServiceNow Virtual Agent for customer-facing support

## Target Users

| Persona | Role in This Scenario |
|---|---|
| **Employee** | Asks how-to and policy questions, finds catalog items |
| **Service Desk Lead / IT Manager** | Reviews knowledge themes, evidence, and gaps |
| **ServiceNow Admin** | Owns knowledge bases, user criteria, and the integration account |
| **Microsoft 365 Admin** | Deploys and monitors connectors, controls agent availability |
| **Delivery Engineer** | Configures the agent, writes instructions, and runs evaluation |

---

## Knowledge Sources Used

| Source | Content | Connector |
|---|---|---|
| ServiceNow Knowledge Base(s) | How-to articles, policies, runbooks, FAQ | ServiceNow Knowledge (synced) |
| ServiceNow Service Catalog | Requestable items and their descriptions | ServiceNow Catalog (synced) |
| SharePoint IT site (optional) | Policy documents not maintained in ServiceNow | Native SharePoint knowledge |

Both ServiceNow connectors are deployed from **Microsoft 365 admin center > Copilot >
Connectors**. Article-level and knowledge-base-level user criteria are carried into
the Graph index. Validate identity mapping and permission trimming before rollout.

## What Actually Goes Wrong

| Symptom | Root cause | Where it is handled |
|---|---|---|
| Same question succeeds, then fails minutes later | Inspect retrieval, permissions, and citations; do not assume a single cause | [3.Runbook.md](3.Runbook.md) — Phase 4 |
| Agent replies in the wrong language | Language instructions compete with the knowledge base language | Runbook — Phase 3 |
| Restricted content is missing or exposed incorrectly | User-criteria flow or integration-account roles are wrong | Runbook — Phase 1 |
| Relative-date article lists are unreliable | Indexed metadata needs explicit date ranges | Runbook — Phase 3 + [4.Sample-prompts.md](4.Sample-prompts.md) |
| Citation links are wrong or truncated | `AccessUrl` does not match the organization's portal URL format | Runbook — Phase 1 |
| Agent invents ticket insights from articles | No actual ticket or feedback source is configured | Runbook — Phases 0, 3, and 4 |
